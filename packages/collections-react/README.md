# CMS collections React

Independent source package for React 19 hosts. It does not import the standalone
CMS application or its SDK. Exports `CollectionEditor`, `LexicalRichTextField`,
`MediaPicker`, `RichContent`, `useContentItems` and content contracts.

Also exports `StructuredPageEditor`, `useContentPages`, `visiblePage` and structured
page/block/layout types. All host page keys use the same editor: introduction and
two quote slots, standalone items and optional groups, per-block publication and
UK scheduling, plus separate draft/published ordering. Supply `pageKey`, the same
authenticated `Api` adapter, a branded full-page preview and dirty-state callback.
Endpoints are `/api/v1/admin/content-pages` and `/api/v1/content-pages`. The delivery
hook refreshes on focus, periodically and at the server's next scheduled transition;
expired groups/items are filtered immediately while a request is pending.

Administration uses GET for reads and POST for every write, directly from the
editors. Both new and existing items/blocks are saved with POST; draft ordering
uses POST to `/{key}/order`. Publication, visibility, deletion and uploads also
use POST. Hosts implement these routes natively; no verb rewriting or PUT/DELETE
compatibility endpoints are required.

Install the published package with
`npm install @brightertools/cms-collections-react`. Import
`@brightertools/cms-collections-react/styles.css` alongside the host's
Bootstrap-compatible form styles. React 19 is a peer dependency supplied by the
host. For local package development, build and pack this directory, then install
the resulting tarball in a consumer.

Supply an `Api` callback that handles the host's authentication, JSON/form bodies,
file blobs, and API errors with an `errors` dictionary. `CollectionEditor` accepts
the content type, draft preview renderer and optional dirty-state callback for
router navigation protection. The delivery hook uses the versioned public
collection API, never an embedded source-data fallback. The host owns routing,
brand renderers, confirmation/navigation behaviour and authorization.

Lexical JSON is the editable source. Public HTML is regenerated by the shared
backend allowlist and sanitized again at rendering. Do not trust client-supplied
HTML. Dates in the editor use Europe/London; API dates are explicit UTC instants.
The package is published under MIT-0; release details are in the repository release notes.

## Listed-item ordering

Announcements, Recent Events, Upcoming Events and Newsletters default to independent
Display order. The native POST `/{id}/move` action receives `direction` (`up`/`down`)
and `orderingVersion`; its response supplies the new version and one-based position.
Admin list results supply `orderingVersion` and `canMoveUp`/`canMoveDown` for each row.
Moves apply immediately and do not publish content drafts. New items start at the top.
Search and alternate sorting disable moves; cross-page moves follow the item and
restore focus. Stories retain date sorting. Host persistence must serialise order
and membership changes and reject stale collection versions.
